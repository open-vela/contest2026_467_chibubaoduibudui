# 官方模拟器健康数据演示视频设计

## 目标

为“腕上节律”制作一段约 60 秒的产品演示视频。应用必须实际运行在官方 `vela-miwear-watch-5.0(开发者大赛)` 虚拟设备中，画面必须展示心率与压力两项 Mock 数据及其变化，并交付带自然沉稳中文男声、内嵌中文字幕的最终 MP4。

同时交付无配音录屏母版、SRT 字幕、按时间码编排的 Markdown 分镜稿和连续旁白稿；工具允许时另附独立旁白音频。

## 已确认的范围

- 运行环境：AIoT 官方工具链和 `vela-miwear-watch-5.0(开发者大赛)` 虚拟设备；
- 数据：模拟应用现有的心率与压力两项健康数据；
- 配音：自然沉稳的普通话男声；
- 时长：约 60 秒；
- 内容：高心率/高压力首页、稳态呼吸、数值下降、节奏拳和结果页；
- 正式应用行为：普通调试构建和发布构建继续读取 `@service.health`，不得默认启用演示数据；
- 输出：写入新的输出目录，不覆盖现有视频和用户当前未提交改动。

## 方案选择

采用“官方虚拟机 + 录制专用 Mock 场景”。官方模拟器底层控制接口可直接注入心率，但当前工具链没有暴露与应用压力分对应的物理传感器接口。为了同时稳定展示两项数据，录制专用构建在应用边界注入可重复的健康样本序列，样本继续经过现有健康数据处理、状态判定、训练节奏和结果计算链路。

不采用以下方案：

1. 仅使用模拟器原生传感器注入，因为无法保证压力分可用；
2. 后期在视频上叠加心率与压力数字，因为这不能证明应用真实接收并处理了模拟数据。

## 数据模拟架构

新增职责单一的演示健康数据源。该数据源按预定时间产生与健康适配层相同形状的样本：

```js
{
  ok: true,
  dataType,
  value,
  timeStamp,
}
```

建议的核心数据轨迹为：

| 阶段 | 心率 | 压力 | 预期表现 |
| --- | ---: | ---: | --- |
| 首页起始 | 112 bpm | 46 分 | 出现需要放缓的状态提示 |
| 稳态训练早期 | 104 bpm | 41 分 | 使用舒缓呼吸节奏 |
| 稳态训练后期 | 94 bpm | 35 分 | 状态逐步改善 |
| 训练结果/节奏拳 | 86 bpm | 31 分 | 结果页显示下降，拳击节拍处于活力档 |

为触发现有趋势与高值判定，每个阶段可重复产生足够数量的样本，但不得修改 `steady.js` 中的业务阈值。所有样本通过页面现有 `applySample()` 入口处理，使以下内容均来自真实业务逻辑：

- 首页心率、压力和提示；
- 稳态训练的初始节奏与周期边界调整；
- 稳态结果页的训练前后值及差值；
- 节奏拳的心率档位和节拍说明；
- 页面现有的数据脉冲视觉反馈。

录制场景必须由显式的演示构建或录制入口开启。默认开发构建和发布构建不得导入或启动演示健康数据源。

## 运行与录制

录制脚本连接当前运行的官方 `Vela_Official_Watch_5_Demo`，等待应用首页和首批健康样本可见后再开始抓帧。脚本使用固定时间轴执行以下动作：

1. 保持首页，展示高心率、高压力和状态提示；
2. 点击“稳态 60”，展示吸气、停留和呼气阶段；
3. 在训练过程中推进健康数据轨迹，展示数值改善；
4. 结束稳态训练并短暂展示前后差值；
5. 返回首页，进入“节奏拳”；
6. 通过官方模拟器加速度传感器接口注入动作，展示目标、命中、得分和连击；
7. 展示节奏拳结果页和心率变化。

画面直接来自官方虚拟机 framebuffer。目标母版为 932×932、10 fps、约 60 秒、H.264 视频；若原始 framebuffer 尺寸不同，只做等比例整数或高质量缩放，不改变应用界面内容。

录制流程必须使用新的帧目录和输出文件名。开始录制前清理只能针对本次新建且经过绝对路径校验的临时帧目录，不能删除既有 `output/video` 内容。

## 成片与旁白

旁白采用自然、克制的产品发布语气，普通话男声。文字稿按最终画面重新编排，而不是沿用当前缺少健康数据展示的旧稿。旁白内容需要明确说明：

- 应用运行于 openvela 官方手表虚拟设备；
- 首页同时感知心率和压力；
- 稳态训练会依据数据选择和调整呼吸节奏；
- 训练后可查看心率和压力变化；
- 节奏拳根据腕部动作评分，并依据心率调整节拍。

最终 MP4 内含旁白音轨和中文字幕。字幕使用画面安全区之外的留白或底部安全位置，不能遮挡表盘中的指标、按钮和人物。另输出不含配音和字幕的录屏母版，便于后续重新剪辑。

## 错误处理与降级

- 官方虚拟机未运行：录制脚本立即失败，报告目标虚拟设备名称，不生成伪成片；
- 应用未进入首页或健康数值未出现：不开始正式抓帧，保留诊断截图或日志；
- Mock 数据未按时间更新：终止该次录制，不使用后期数字叠加修补；
- 加速度注入失败：保留稳态段证据并重新录制节奏拳段，不伪造命中画面；
- 中文男声音色不可用：改用本机或可用服务提供的普通话男声，保持男声要求，不以女声替代；
- 音频时长与画面不一致：以画面时间码为准调整停顿或语速，不截断关键句；
- 成片编码失败：保留原始帧和独立音频，重新编码到 H.264/AAC。

## 测试与验收

### 代码验证

录制前执行：

```powershell
npm test
npm run build
npm run build:release
```

新增自动测试应验证：

- 演示健康场景按顺序生成心率与压力样本；
- 样本类型和值符合页面现有处理入口；
- 演示源只能由显式录制配置启用；
- 普通构建与发布构建仍使用 `@service.health`；
- 既有训练、拳击、生命周期和组件契约测试继续通过。

### 画面验证

从成片抽取并检查以下关键帧：

1. 首页同时显示有效心率和压力，且不为 `--`；
2. 首页出现与高值数据一致的状态提示；
3. 稳态训练展示至少两个呼吸阶段；
4. 训练结果展示心率与压力的前后值和负向差值；
5. 节奏拳展示有效心率档位、命中、得分和连击；
6. 拳击结果页展示训练期间心率变化；
7. 所有关键文字、数值、人物和按钮均未被圆形边缘裁切。

### 媒体验证

最终交付必须满足：

- MP4 时长约 60 秒；
- 画面为正方形、H.264 编码；
- 最终版包含可识别的普通话男声音轨；
- 中文字幕与旁白时间基本同步；
- 旁白、字幕和画面描述的数值及功能一致；
- 无配音母版、SRT 和 Markdown 文字稿均可独立使用。

```text
  腕上节律-官方模拟器健康数据演示-旁白.wav
  腕上节律-官方模拟器健康数据演示-字幕.srt
  腕上节律-官方模拟器健康数据演示-文字稿.md
  frames/
  verification/
```

若独立旁白音频受音色工具限制无法生成，必须在交付说明中明确指出；最终带中文男声的 MP4 仍是必需项。

## 完成标准

只有同时满足以下条件才视为完成：

1. 官方 `vela-miwear-watch-5.0(开发者大赛)` 虚拟设备真实运行并产生录屏；
2. 首页和训练结果明确展示心率与压力两项 Mock 数据；
3. 数据变化通过现有业务链路影响状态、节奏或结果，而非后期叠加；
4. 最终 MP4 内置自然沉稳的普通话男声和中文字幕；
5. 自动测试、开发构建和发布构建通过；
6. 关键帧和媒体属性经过实际检查；
7. 新产物不覆盖现有视频，也不夹带或丢失用户已有未提交改动。
